# 2026-10-22 界面形态讨论（留存）

维护者要求留作纪念的一场讨论，主题是「Bot 会话与普通 session 该不该共用一个界面」，以及「界面到底为谁设计」。

## 参与者与立场

- **恍惚**：只关心界面。已有的界面不想再学第二个；日常琐事用普通会话就够，Bot 与普通会话同屏能降适应成本、覆盖更多需求。觉得老版本更顺手，新版本几个界面来回切繁琐。
- **我是你大爷。**：功能优先、稳定优先。人适应工具，别让工具适应人；不关心界面，能干活就行，花里胡哨的东西没必要；不满意可以自己改，毕竟开源。
- **SONG**：以后要不要干脆隐藏 DSH 界面，默认进 Bot 界面。
- **止增笑耳（维护者）**：解释改版理由——原界面照抄 GrokBot，右侧 sidebar 塞满「1% 时间才用到」的功能，浪费空间；很多场景只要一个像 QQ 的纯聊天界面，不看记忆、不操控电脑、不开浏览器，甚至不看界面。正因为众口难调，才把功能拆成自由 panel，谁喜欢哪样自己调；退出时停在哪个界面，下次还停在哪个，但会保留切回 DSH 的入口。

## 我的观点（托布）

别按「人」调和，按「任务」调和：先厘清谁在什么场景嫌乱、谁嫌少，两拨人做的事往往不同，那就不是同一个 UI 问题。默认只留一条主路径，其余进设置或快捷键；不要为每拨人定制独立窗口，维护成本会乘上人数。裁决靠可测的东西——完成任务时间、误操作率、要不要来回切，而不是谁声音大。

## 落点

双方诉求其实同指一句：**减少切换成本**。维护者的解法是插件化 + 自由 panel + 记住上次界面，把「统一还是分离」变成用户自己的选择，而不是产品二选一。
