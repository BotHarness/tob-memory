## Summary

`secret_cli` with an injected secret (program `gh`, `GH_TOKEN` supplied from a configured secret account) intermittently refuses to run in a local DM context with:

```
Select one live accepted IM source_event_id for private input
```

Two identical structured calls failed, then a later identical call succeeded with exit code 0. There is no stable reproduction.

## Actual behaviour

- The same structured call (same account, same secret reference, same program and environment variable name) was refused twice in a local DM.
- The error asks for an IM source selection, but the tool signature has no parameter for it.
- A later identical call succeeded.

## Expected behaviour

A configured secret account can be used in a local DM without an IM source event, or the error should explain how to supply or select one.

## Error text

```
Select one live accepted IM source_event_id for private input
```

## Impact

Blocked read-only verification and issue filing while the credentials themselves were valid.

## Workaround

Retry the same call; it may succeed.

## Notes

Separate known usage constraint: passing a program path (for example `/usr/bin/gh`) is rejected with `program must be a bare program name without a path`. That is a distinct validation rule and is not the cause of the intermittent refusal above.

## Environment

Unknown product version. Observed in a local DM workflow while more than one external source was present.
