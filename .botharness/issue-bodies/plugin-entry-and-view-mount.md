## 背景

群内在讨论插件体验时提出两点（SUG-40）。二者相关但不是一回事：

### 一、缺少统一的插件入口

现状：安装入口分散（市场、按包名安装、手动路径），装完也没有一个地方能看清「我装了什么、各自能做什么」。用户找插件靠记忆和搜索。

期望：一个有稳定位置的插件入口（列表 + 状态 + 能做什么 + 开关）。

### 二、缺少插件视图挂载点

现状：插件没有往界面里挂自己视图的位置，结果只能靠一段文字汇报。比如生图插件只能贴个链接或一段说明，没法在会话里直接给一张卡片。

期望：划出少量稳定的挂载点，例如：侧栏项、会话内卡片位、设置页、状态栏。社区插件按契约填写，自建插件保留自由。

## 为什么值得做

- 入口不是「难找」，是没有；视图挂载点缺了，插件永远像外挂。
- 有了这两块，第 N 个插件的边际体验才不会继续变差。

## 建议的最小范围

先不做完整框架，只定 3 个落点与它们的契约：
1. 侧栏项（图标 + 标题 + 打开一个面板）
2. 会话内卡片（渲染一块结构化内容）
3. 设置页分组（键值表单）
